## לפני שמתחילות

פתחו את ה־Terminal בתוך סביבת ה־Linux שלכן.

### כללי עבודה חשובים

1. לפני שיוצרות, מוחקות או מריצות קבצים — בדקו איפה אתן נמצאות בעזרת `pwd`.
2. לפני שמוחקות — בדקו מה יש בתיקייה בעזרת `ls`.
3. אל תשתמשו ב־`sudo` בתרגול הזה.
4. אל תריצו `rm` על קבצים או תיקיות שלא יצרתן בעצמכן.
5. אם פקודה לא ברורה לכן, אפשר לקרוא עליה בעזרת `man`.

```bash
man ls
```

ליציאה ממסך ה־`man`, לחצו על `q`.

# חלק א — היכרות עם ה־Terminal

## משימה 1 — מי אני ואיפה אני?

הריצו:

```bash
whoami
pwd
```

### שאלות

1. מהו שם המשתמשת שלכן?
2. באיזו ספרייה אתן נמצאות?
3. האם זו תיקיית הבית שלכן?

<details>
<summary>פתרון והסבר</summary>

- `whoami` מדפיסה את שם המשתמשת הנוכחית.
- `pwd` הוא קיצור של `Print Working Directory`, והוא מדפיס את הנתיב של הספרייה הנוכחית.
- בדרך כלל, כאשר פותחים Terminal, מתחילים בתיקיית הבית של המשתמשת, למשל `/home/student`.

</details>

```bash
echo Hello Linux!
```

### שאלות

1. מה עושה `echo`?
2. האם היא יוצרת קובץ?
3. למה במקרה השני השתמשנו במירכאות?

<details>
<summary>פתרון והסבר</summary>

- `echo` מדפיסה טקסט למסך.
- ללא סימן נוסף, היא לא יוצרת קובץ.

</details>

## משימה 4 — יצירת מבנה תיקיות

בתוך `linux-practice`, צרו את המבנה הבא:

```text
linux-practice/
├── notes/
├── projects/
│   ├── project-a/
│   └── project-b/
└── temp/
```

נסו קודם ליצור את כל התיקיות בעזרת `mkdir`.

### שאלות

1. באיזו פקודה משתמשים כדי ליצור תיקייה?
2. איך אפשר ליצור כמה תיקיות מקוננות בפקודה אחת?
3. מה עושה הדגל `-p`?

<details>
<summary>פתרון אפשרי — דרך הדרגתית</summary>

```bash
mkdir notes
mkdir projects
mkdir projects/project-a
mkdir projects/project-b
mkdir temp
```

</details>

<details>
<summary>פתרון אפשרי — בעזרת -p</summary>

```bash
mkdir -p notes projects/project-a projects/project-b temp
```

`-p` מאפשר ליצור גם תיקיות אב חסרות בדרך.

</details>

## משימה 5 — ניווט בין תיקיות

בצעו את הפעולות הבאות:

1. ודאו שאתן בתוך `linux-practice`.
2. היכנסו ל־`projects`.
3. היכנסו ל־`project-a`.
4. עלו תיקייה אחת למעלה.
5. עברו לתיקיית הבית שלכן.
6. עברו לספריית השורש של מערכת הקבצים.

בכל שלב, הריצו `pwd` כדי לבדוק איפה אתן נמצאות.

<details>
<summary>פתרון אפשרי</summary>

```bash
cd ~/linux-practice
pwd

cd projects
pwd

cd project-a
pwd

cd ..
pwd

cd
pwd

cd /
pwd
```

</details>

### שאלות

1. מה עושה `cd ..`?
2. מה עושה `cd` ללא פרמטרים?
3. מה עושה `cd /`?
4. מה ההבדל בין `/` לבין `/root`?

<details>
<summary>תשובות</summary>

1. `cd ..` עולה לתיקיית האב — תיקייה אחת למעלה.
2. `cd` ללא פרמטרים מחזירה בדרך כלל לתיקיית הבית של המשתמשת.
3. `cd /` מעבירה לספריית השורש של מערכת הקבצים.
4. `/` היא ספריית השורש של כל מערכת הקבצים. `/root` היא בדרך כלל תיקיית הבית של משתמש העל, שנקרא `root`.

</details>

## משימה 6 — צפייה בתוכן של תיקיות

עברו שוב ל־`linux-practice` והריצו:

```bash
ls
ls -l
ls -la
```

### שאלות

1. מה ההבדל בין `ls` לבין `ls -l`?
2. מה מוסיף הדגל `-a`?
3. למה יש קבצים שמתחילים בנקודה, למשל `.config`?

<details>
<summary>תשובות</summary>

- `ls` מציגה רשימה בסיסית של קבצים ותיקיות.
- `ls -l` מציגה מידע מפורט יותר, למשל הרשאות, בעלים, גודל ותאריך שינוי.
- `ls -a` מציגה גם קבצים מוסתרים.
- ב־Linux, שם שמתחיל בנקודה מסמן בדרך כלל קובץ או תיקייה מוסתרים, לעיתים קרובות של הגדרות.

</details>

## משימה 8 — כתיבה לקובץ עם Redirection

כתבו את הטקסט הבא לתוך `linux.txt`:

```text
Linux היא מערכת הפעלה נפוצה בשרתים.
```

אחר כך הציגו את תוכן הקובץ למסך.

<details>
<summary>רמז</summary>

השתמשו ב־`echo`, בסימן `>`, ואחר כך ב־`cat`.

</details>

<details>
<summary>פתרון אפשרי</summary>

```bash
echo "Linux היא מערכת הפעלה נפוצה בשרתים." > linux.txt
cat linux.txt
```

</details>

### שאלות

1. מה עושה `>`?
2. מה יקרה אם `linux.txt` כבר קיים?
3. מה ההבדל בין `>` לבין `>>`?

<details>
<summary>תשובות</summary>

1. `>` מפנה את הפלט של הפקודה לקובץ.
2. תוכן הקובץ הקיים יידרס ויוחלף בתוכן החדש.
3. `>` דורס את הקובץ, ואילו `>>` מוסיף טקסט לסוף הקובץ בלי למחוק את התוכן שכבר קיים.

</details>

## משימה 10 — קריאת קובץ

צרו קובץ בשם `long-notes.txt` עם לפחות 15 שורות קצרות.

אפשר לעשות זאת בעזרת `nano`, או להוסיף שורות אחת־אחת בעזרת `echo >>`.

אחר כך:

1. הציגו את כל הקובץ בעזרת `cat`.
2. פתחו אותו בעזרת `less`.
3. צאו מ־`less`.

<details>
<summary>פתרון אפשרי עם nano</summary>

```bash
nano long-notes.txt
```

שמרו עם `Ctrl + O`, לחצו Enter, וצאו עם `Ctrl + X`.

אחר כך:

```bash
cat long-notes.txt
less long-notes.txt
```

ליציאה מ־`less` לחצו `q`.

</details>

### שאלות

1. מתי `less` נוחה יותר מ־`cat`?
2. איך יוצאים מ־`less`?
3. איזה עורך טקסט בסיסי אפשר לפתוח מתוך Terminal?

<details>
<summary>תשובות</summary>

1. `less` נוחה יותר לקבצים ארוכים, כי אפשר לגלול ולקרוא בהדרגה.
2. לוחצים `q`.
3. `nano` הוא עורך טקסט בסיסי ונוח יחסית למתחילות.

</details>

# חלק ה — תהליכים

## משימה 12 — זיהוי המשתמשת והתהליכים שלה

קודם בדקו את שם המשתמשת שלכן:

```bash
whoami
```

אחר כך הריצו:


החליפו את `YOUR_USERNAME` בשם שקיבלתן מ־`whoami`.

### שאלות

1. מה עושה `ps`?
2. מה משמעות הדגל `-u`?
3. האם אתן מזהות תהליך של Shell, למשל `bash` או `zsh`?

<details>
<summary>תשובות</summary>

1. `ps` מציגה מידע על תהליכים.
2. `-u` מסננת תהליכים לפי משתמשת.
3. התוצאה תלויה בסוג ה־Shell שמותקן אצלכן. ייתכן שתראו `bash`, `zsh` או Shell אחר.

</details>

## משימה 14 — top

הריצו:

```bash
top
```

נסו לזהות:

- עומס CPU.
- שימוש בזיכרון.
- שמות של תהליכים.
- PID של תהליך כלשהו.

ליציאה לחצו `q`.

### שאלות

1. מה זה PID?
2. למה `top` לא מסתיימת מיד?
3. מה יקרה אם תוכנה משתמשת בהרבה CPU או זיכרון?

<details>
<summary>תשובות</summary>

1. PID הוא `Process ID` — מספר מזהה של תהליך.
2. `top` היא תוכנה אינטראקטיבית שמתעדכנת בזמן אמת.
3. היא עלולה להאט את המחשב או לגרום לבעיות ביצועים.

</details>

# חלק ז — אתגר מסכם

## משימה 16 — בניית “פרויקט” קטן דרך ה־Terminal

צרו בתוך `linux-practice` את המבנה הבא:

```text
mini-project/
├── src/
│   └── app.js
├── docs/
│   └── README.txt
└── logs/
    └── app.log
```

דרישות:

1. ב־`src/app.js` כתבו קוד JavaScript שמדפיס:

```text
Mini project is running
```

2. ב־`docs/README.txt` כתבו לפחות שתי שורות:
   - שם הפרויקט.
   - מה הוא עושה.
3. ב־`logs/app.log` כתבו שורת לוג אחת, למשל `Application started`.
4. הציגו את התוכן של כל אחד משלושת הקבצים.
5. הריצו את `app.js` באמצעות Node.js.

<details>
<summary>פתרון אפשרי</summary>

```bash
cd ~/linux-practice

mkdir -p mini-project/src mini-project/docs mini-project/logs

echo "console.log('Mini project is running')" > mini-project/src/app.js

echo "Mini Project" > mini-project/docs/README.txt
echo "This project demonstrates Linux commands." >> mini-project/docs/README.txt

echo "Application started" > mini-project/logs/app.log

cat mini-project/src/app.js
cat mini-project/docs/README.txt
cat mini-project/logs/app.log

node mini-project/src/app.js
```

</details>

# חלק ח — שאלות חזרה מהשיעור

נסו לענות בלי להסתכל בפתרונות.

## Linux ומכונות וירטואליות

1. מהי מערכת הפעלה?
2. מהי Linux?
3. מהי Distribution?
4. תנו דוגמה להפצת Linux.
5. למה Linux נפוצה בשרתים?
6. מהי מכונה וירטואלית?
7. מה ההבדל בין המחשב הפיזי למכונה וירטואלית?
8. למה נוח לפתח בסביבה שדומה לסביבת ה־Production?

<details>
<summary>תשובות</summary>

1. מערכת הפעלה היא התוכנה שמנהלת את משאבי המחשב, הקבצים, התוכנות, הזיכרון, המשתמשים והחומרה.
2. Linux היא משפחה של מערכות הפעלה נפוצות במיוחד בשרתים, פיתוח וענן.
3. Distribution היא גרסה או הפצה של Linux עם בחירות שונות של כלים, הגדרות ותוכנות.
4. למשל Ubuntu, Debian, Fedora או Red Hat.
5. בגלל יציבות, גמישות, קוד פתוח, יעילות ועלויות רישוי נמוכות או ללא עלות.
6. מכונה וירטואלית היא מחשב מדומה שרץ בתוך מחשב פיזי.
7. המחשב הפיזי הוא המחשב האמיתי והחומרה שלו. המכונה הווירטואלית משתמשת בחלק מהמשאבים שלו, אבל מריצה מערכת הפעלה וסביבה נפרדת.
8. כי כך מצמצמים הבדלים והפתעות בין סביבת הפיתוח לבין הסביבה שבה המערכת האמיתית תרוץ.

</details>

## Terminal ו־Shell

1. מהו Terminal?
2. מהו Shell?
3. מה ההבדל בין GUI ל־CLI?
4. מהו Bash?
5. מה עושה `exit`?
6. למה עבודה ב־CLI שימושית למפתחות?

<details>
<summary>תשובות</summary>

1. Terminal היא התוכנה או החלון שבו אנו מקלידות פקודות.
2. Shell היא התוכנה שמפרשת את הפקודות ומעבירה אותן למערכת ההפעלה.
3. GUI הוא ממשק גרפי עם חלונות, כפתורים ועכבר. CLI הוא ממשק טקסטואלי המבוסס על פקודות.
4. Bash הוא סוג נפוץ של Shell.
5. `exit` מסיימת את סשן ה־Shell הנוכחי.
6. כי CLI מאפשרת עבודה מהירה, מדויקת, ניתנת לאוטומציה, ולעיתים גם עבודה מרחוק על שרתים ללא ממשק גרפי.

</details>

## מבנה ספריות ופקודות

1. מה מסמל `/` ב־Linux?
2. מה עושה `pwd`?
3. מה עושה `ls`?
4. מה עושה `cd`?
5. מה עושה `cd ..`?
6. מה עושה `cd` ללא פרמטר?
7. מה עושה `mkdir`?
8. מה עושה `touch`?
9. מה עושה `cat`?
10. מה ההבדל בין `cat` ל־`less`?
11. מה עושה `man`?
12. מה עושה `whoami`?
13. מה עושה `grep`?
14. מה עושה `>`?
15. מה ההבדל בין `>` ל־`>>`?

<details>
<summary>תשובות</summary>

1. `/` מסמלת את ספריית השורש של מערכת הקבצים.
2. `pwd` מדפיסה את הנתיב של הספרייה הנוכחית.
3. `ls` מציגה קבצים ותיקיות.
4. `cd` מעבירה בין תיקיות.
5. `cd ..` עולה לתיקיית האב.
6. `cd` ללא פרמטרים מחזירה בדרך כלל לתיקיית הבית.
7. `mkdir` יוצרת תיקייה.
8. `touch` יוצרת קובץ ריק, אם הוא לא קיים.
9. `cat` מדפיסה את תוכן הקובץ למסך.
10. `cat` מדפיסה את כל הקובץ בבת אחת; `less` נוחה יותר לקריאה הדרגתית של קבצים ארוכים.
11. `man` פותחת מדריך על פקודה.
12. `whoami` מדפיסה את שם המשתמשת הנוכחית.
13. `grep` מחפשת ומציגה שורות שמתאימות לטקסט או לתבנית.
14. `>` מפנה פלט לקובץ ובדרך כלל דורס את התוכן הקיים.
15. `>` דורס את הקובץ; `>>` מוסיף תוכן לסוף הקובץ.

</details>

## תהליכים

1. מהו Process?
2. מה ההבדל בין קובץ קוד לתהליך?
3. מהו PID?
4. מה עושה `ps`?
5. מה עושה `ps -u username`?
6. מה עושה `top`?
7. איך יוצאים מ־`top`?
8. למה פתיחת Terminal נוסף יכולה ליצור תהליך נוסף?

<details>
<summary>תשובות</summary>

1. Process הוא מופע של תוכנה שרצה בפועל במערכת ההפעלה.
2. קובץ קוד נשמר על הדיסק; תהליך הוא התוכנה בזמן שהיא רצה.
3. PID הוא מספר מזהה של תהליך.
4. `ps` מציגה מידע על תהליכים.
5. היא מציגה תהליכים של משתמשת מסוימת.
6. `top` מציגה תהליכים ומשאבים בזמן אמת.
7. יוצאים עם `q`.
8. כי לכל חלון Terminal יש בדרך כלל סשן Shell משלו, שרץ כתהליך נפרד.

</details>
